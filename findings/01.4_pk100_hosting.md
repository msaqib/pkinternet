# Findings 1.4 — Where 100 Pakistani websites are hosted (PK100)

**Author:** Rayan Atif
**Source:** Experiment 1.4 (`experiments/01.4_pk100_hosting/`). Two passes:
**Pass A** — hosting identity (DNS → Team Cymru ASN → ip-api geo) from the project
machine (PK vantage); **Pass B** — ICMP Paris traceroute from RIPE probe **64078**
(Transworld/TES-PL AS135407, Rawalpindi). Combined with Experiment 01's list.

Companion to `findings/01_hosting_and_routing_analysis.md`.

## Headline

For a **government / education / utility**–heavy list of 100 PK websites, **99% are
hosted inside Pakistan** (1 on Cloudflare, 0 on a foreign server). This is the
**opposite** of Exp 01's commercial/news/banking list (~75% offshore/CDN): **the public
sector self-hosts domestically; the private sector goes offshore.** Sector is the
strongest predictor of where a Pakistani site is hosted.

## Pass B — path from a real user (probe 64078, Transworld) : hosting-local ≠ path-local

ICMP traceroute from Transworld to all 100. Readable paths: `results/routes_pass_b_*.txt`.

- **Reachability:** only **31/100** destinations answered the ICMP probe; **58** were
  path-traced but the server stayed silent, **11** gave no path. **All 69 not-reached
  are PK gov/public servers that firewall ICMP** — a security posture, not a hosting
  fault (hosting comes from Pass A/DNS, which needs no ICMP).
- **Median RTT to PK-hosted sites ≈ 34 ms** (min 4 ms) — most are genuinely local from
  Transworld.
- **The hairpin — key finding:** **18 PK-hosted *government* sites, all on Cybernet's
  federal block (`203.101.184.x`), are reached at ~195–216 ms from Transworld.** They
  are hosted *inside Pakistan* but a Transworld user reaches them via an **international
  hairpin** — the trace goes `TES → Transworld → Equinix-Singapore → Prolexic (Akamai
  DDoS) NL/US`, and the origin is hidden behind Prolexic. **The site is local; the path
  is not.** This is the tromboning story landing directly on government hosting, and it
  is exactly the vantage-dependence Pass B exists to expose.

## Caveats

- **Hosting = IP's ASN/geo** (Pass A). For anycast CDNs the registered country lies;
  the one Cloudflare site (secp.gov.pk) needs `/cdn-cgi/trace` for its true PoP.
- **Pass B RTT** is the destination RTT for the 31 reached, else the last-responding-hop
  RTT — treat the buckets as *path* latency, not confirmed serving RTT.
- DNS resolved once from a PK vantage; ~8% of PK sites are GeoDNS (Exp 1.1), not
  material for this gov-heavy list.
- Single Pass-B vantage (Transworld). The ~200 ms gov hairpin is *Transworld's* route;
  other ISPs may reach the Cybernet block locally (as in the Worldcall RQ4 asymmetry).

## Takeaway for the PKIX story

Government content is **already in Pakistan** — the inefficiency is not hosting but
**routing**: a Transworld user hairpins to Singapore/US to reach PK-hosted government
sites. Fixing that is a peering/PKIX problem, not a hosting one. The commercial half,
by contrast, is a genuine *hosting* problem (60% offshore/CDN).
